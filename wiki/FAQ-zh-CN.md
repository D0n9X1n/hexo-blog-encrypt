# 常见问题

[English](FAQ)

常见问题, 按被问到的频率排序.

## 密码会通过网络发送吗?

**不会.** 加密在你本机执行 `hexo generate` 时完成. 解密完全在读者的浏览器中进行. 读者输入的密码不会离开他们的浏览器.

## 可以加密整个站点吗?

可以: 给每篇文章打上注册表中的某个标签, 或在每篇文章的文章信息头中设置 `password:`. 全局配置中没有 "全部加密" 开关, 因为它很容易误伤 (你的首页 / 归档 / RSS 会悄无声息地失效).

## Google 还会索引我的加密文章吗?

加密后的正文是不透明的密文, 搜索引擎无法读取或排名. 页面的 **标题**, **日期**, **标签**, 以及 **`<!-- more -->` 分隔符之前** 的文字仍会被索引 (它们在 HTML 中是明文). 如果你完全不希望文章被索引, 请通过主题添加 `noindex` meta 标签.

## 读者 "查看源代码" 能看到文章内容吗?

源代码中的加密正文是密文. 分享 / 查看 / 保存源代码都是安全的: 没有密码它毫无用处. 密码输入框以及摘要 / 预览文字和其它 HTML 一样在源代码中可见.

## 忘记密码怎么办?

无法恢复. 插件不会在任何地方保存密码: 它在构建时从密码派生密钥, 用该密钥加密, 然后丢弃密钥. 如果你记不起密码, 这篇文章就 **永久** 无法读取. 请使用密码管理器.

## 不同文章可以用不同密码吗?

可以. 每篇文章都可以在文章信息头中设置自己的 `password:`. 使用不同密码的文章可以在同一站点共存, 互不干扰 (每篇文章独立的 salt + nonce 保证它们不共享密钥材料).

## `wrong_pass_message` 和 `wrong_hash_message` 有什么区别?

在 v3 中它们是不同的: 一个用于 "密码错误", 一个用于 "密文被篡改". v4 将二者合并: AES-GCM 认证失败在密码学上与密码错误无法区分 (这是一项安全特性, 不是限制). `wrong_hash_message` 现在是 `wrong_pass_message` 的别名, 并会给出弃用警告. 请使用 `wrong_pass_message`.

## 为什么每次重新构建后加密文章的 HTML 都会变?

每次加密都会生成新的 **nonce** (12 个随机字节). 对 AES-GCM 来说, **重用 nonce 是灾难性的** (会泄露明文的 XOR), 所以插件总是使用新的 nonce. 因此每次构建密文都会逐字节变化.

如果你通过 CDN 提供服务, 这意味着:
- 每次重新构建后都要清除缓存
- 或者: 为 `*.html` 配置较短的 TTL
- 或者: 将 CDN 配置为每次请求都重新验证 (这违背了使用 CDN 的初衷, 但是正确的)

浏览器端 bundle (`lib/hbe.bundle.<hash>.js`) 带有 **内容哈希**, 只有 bundle 源码变化时才会改变, 因此可以永久缓存: 只有文章 HTML 需要较短的 TTL.

## 为什么部署后解密失败, 本地却正常?

99 % 的情况是: 部署的站点使用的是普通 HTTP. Web Crypto 需要 HTTPS (或 localhost). 参见 [浏览器支持](Browser-Support-zh-CN).

其它原因:
- 页面 URL 带有被 CDN 去掉的 hash 片段 (bundle 从页面 DOM 读取, 而不是从 URL 读取)
- service worker 提供了过期的 bundle, 无法识别 v4 数据格式

## 为什么解密很慢?

每次尝试解密时, PBKDF2 KDF 都会运行 `kdf.iterations` 轮 (默认 250 000). 在 2024 年的笔记本上约 30 ms. 在 2015 年的手机上可能超过 300 ms. 降低迭代次数可以加快速度, 但会削弱抗暴力破解能力: 权衡见 [安全模型](Security-Model-zh-CN) 页面.

## 可以配合 `hexo-renderer-pug` / 非 marked 渲染器使用吗?

可以: 插件处理的是 Hexo 渲染器完成之后输出的 HTML. Hexo 支持的任何渲染器都可以. 唯一的要求是你的渲染器必须输出有效的 HTML.

## 支持 Hexo 的 `--draft` 参数吗?

支持. 草稿与普通文章一样渲染, 加密过滤器也以相同方式运行.

## 可以加密页面 (而非文章) 吗?

过滤器注册在 `after_post_render` 上. 页面走的是另一条渲染流程. 原则上可以做到, 但目前尚未接入. 欢迎提交 PR.

## 解密后如何让语法高亮 / MathJax / mermaid 生效?

使用 [`hexo-blog-decrypt` 事件](Callbacks-and-MathJax-zh-CN). 这些库在页面加载时的处理跳过了你的加密文章 (它们只看到了密文); 你需要在解密后的 DOM 上重新运行它们. 该页面有完整示例.

## 可以自定义密码输入框的 HTML 吗?

可以: 编写一个 [主题](Themes-zh-CN). Wiki 中有通过复制 `lib/hbe.default.html` 新增主题的说明.

## 有 Vue / React / Svelte 组件吗?

没有. 本插件在 Hexo 构建时工作. 浏览器端 bundle 是纯原生 JS, 不依赖任何框架.

## 为什么 bundle 只有约 5 KB? 看起来很小.

因为它是刻意精简的. 实际的加密由 Web Crypto 完成; bundle 只负责 DOM + UI 衔接 + KDF / 解密的调度. 没有 CryptoJS, 没有 polyfill, 没有动画库: 主题使用纯 CSS.

## 维护状态如何?

积极维护中. v4 是 2026 年的重新设计; 次要版本按需发布. 欢迎提交 issue 和 PR.
